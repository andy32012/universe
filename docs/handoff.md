# 交接：iPad App、效能量測與 Godot 移植計畫

2026-10-08 的工作紀錄，給接手的人（包括下一個 Claude Code 工作階段）。

## 使用者的決定

- **要原生 App，把 iPad 的效能全部發揮出來**，選擇用 **Godot**（4.5 以後的版本，iPad 上使用 Metal 驅動與 MetalFX 升頻）重寫，分階段移植。
- **畫質不能降**。可以接受**載入時間變長**，換取遊玩時更順。
- 最後想**上架 App Store 販售**。
- 想加入「**宇宙日記**」：在宇宙中某個地方寫一張紙，寫完丟出去，紙會隨著「宇宙的風」飄到很遠的地方。初步構想是在太陽系內被太陽風（真實速度約每秒 400 公里）往外吹，離開太陽系後隨銀河系旋轉。遊戲是照真實時間運行的，過幾個月再回來，紙會飄得很遠。日記內容要存在原生儲存空間（之後可考慮 iCloud 同步），不可寫進記錄檔。
- 使用者有 **iPad Pro（M5）**，型號 iPad17,3，iPadOS 27.0.1，螢幕 2064×2752、120 Hz；還有一台 **Windows 電腦**；**沒有 Mac**。

## 目前的狀態

- 網頁版遊戲在 `main`（`index.html`，約 7,500 行，three.js r128 + WebGL2）。
- iPad 外殼 App 在分支 `claude/inspiring-dirac-fjf6zi`，尚未合併到 `main`：
  - `ios/`：SwiftUI + `WKWebView` 外殼，遊戲檔案打包在 App 裡，從 `universe://localhost/` 提供。
  - `ios/Universe/Diagnostics.swift`：注入頁面的記錄功能，記錄錯誤、載入步驟、每 5 秒的幀率與 CPU 使用率。每 15 秒挑一幀分段量 GPU 時間（攔截 `THREE.WebGLRenderer` 的 `render` 與 `renderBufferDirect`，前後以 `finish()` 加一次 1 像素讀取等待 GPU）。遊戲「設定」面板最下面有「分享記錄檔」按鈕。
  - `.github/workflows/ios.yml`：GitHub 的 macOS 主機編譯 App，每次都產出未簽名的 `Universe-unsigned.ipa`（run artifact）。版號等於 workflow 的執行次數。
- 安裝方式：Windows 上用 **Sideloadly** 加免費 Apple ID 安裝（7 天後過期、最多 3 個 App、每週 10 個 App ID）。iPad 需開啟開發者模式，並在「VPN 與裝置管理」信任開發者。
  - Sideloadly 曾在「Looking up app ID」之後閃退，完全移除重裝後就好了。目前安裝時不勾「Enable File Sharing」。
  - App 的資料夾一直沒有出現在「檔案」App 裡，所以改用「分享記錄檔」按鈕傳送記錄。

## 量測結果（第 9 版，iPad 上的真實數據）

| 位置 | 幀率 | CPU 最忙的核心 |
|---|---|---|
| 太陽系（地球附近） | 約 12 | 11–17% |
| 太陽系的邊緣 | 約 6 | 11–18% |
| 銀河系 | 約 2 | 6–18% |

- 載入 5.9 秒，沒有錯誤、閃退、過熱或記憶體警告。
- 遊戲程式每幀的時間有時長達 100–460 毫秒，但 CPU 很閒：這是 WebKit 在 GPU 跟不上時讓頁面的繪圖呼叫排隊等待。**瓶頸是 GPU，而且不只是海王星，而是整個遊戲。**
- 在電腦 Chromium（SwiftShader 軟體 GPU）上分段量測：體積氣體那一步（`volScene` → `rtVol`）約佔 81%，最花時間的是銀河系體積著色器 `GALV_FS`。iPad 上的分段數據要等第 10 版的記錄檔。

## 高畫質下的主要負擔（`index.html`）

- `QUALITY_MODE = 'high'`，固定不變。像素密度上限 2，主畫面最多 8.4 百萬像素，使用 HDR 半浮點與多重取樣反鋸齒。
- 體積氣體：`NEB_SAMPLES` 128、`GAL_SAMPLES` 96，`volScale` 1.0（全解析度）。迴圈上限 `NEB_STEPS` 160、`GAL_STEPS` 128。
- 海王星大氣 `nepQuality()`：高畫質為全解析度、96 步，每步再往太陽方向走 5 步，而且每幀重算，沒有快取。
- 也有 WebGPU 的 HDR 顯示路徑（`hdrPresent`），只有使用者打開 HDR 時才會執行。

## 不降畫質的加速想法（移植時一併採用）

1. **銀河系在載入時烘焙成 360 度全景圖**：在太陽附近時，銀河的樣子幾乎不隨位置改變。遠離太陽或開望遠鏡放大時，改回即時計算。要注意記憶體：HDR 全景圖若要跟螢幕一樣清楚，會用到數百 MB。
2. **海王星大氣的陽光預先算成 3D 表**，取代每步往太陽走 5 步。
3. **分幀累積**：每幀只算一部分像素，用重投影把前幾幀疊起來，靜止時與全解析度相同。
4. **MetalFX 時間升頻**（Godot 的 3D 縮放模式）。

## Godot 移植的階段

1. Metal 繪圖核心、120 Hz、視角控制，以及**銀河系**（最重的部分），量出 M5 上的幀率。
2. 星空、太陽、行星、軌道計算（`38-ephemeris.js`、`40-solar.js`）。
3. 星雲、黑洞、海王星大氣、彗星、月球與火星的實測地形、星團。
4. 設定、探索搜尋、資訊面板。
5. 宇宙日記、上架。

注意：宇宙的尺度遠超過單精度浮點數的範圍，要沿用網頁版處理大尺度的方式（相對位置、分層尺度）。網頁版和現有的 App 在移植期間繼續保留。
